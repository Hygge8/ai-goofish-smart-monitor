# 同类项目取舍分析

本项目以 `Usagi-org/ai-goofish-monitor` 为主底座，同时参考 `banbanzhige/ai-goofish-monitor-QB`、`ddCat-main/ai-goofish` 和 `ponyletter/py310GoofishAiBot` 的设计方向。

## 取舍结论

| 项目 | 值得保留 | 不直接照搬 | 本项目做法 |
|---|---|---|---|
| Usagi | Web 管理、多任务、定时、账号与代理轮换、多渠道通知、Docker 部署 | 不再重复造基础框架 | 直接作为主底座 |
| QB | 三维评分、图片分析、卖家画像、钉钉图文卡片、样本标注 | 多用户、权限和 PostgreSQL 部署较重 | 优先吸收钉钉卡片、评分看板和样本标注思路 |
| ddCat | 轻量 Web、代理管理、频率控制、邮件通知、日志统计 | 当前框架已换成 Usagi，不替换主架构 | 吸收限速、健康检查、邮件通知和日志统计思路 |
| py310GoofishAiBot | AI 客服、消息队列、意图识别、违禁词过滤、人工接管、Ollama 本地模型、聊天上下文 | 它偏“卖家自动客服”，不是“商品监控推荐”，不替换当前监控主链路 | 后续可吸收客服自动回复、议价策略、安全过滤和本地模型思路 |

## py310GoofishAiBot 额外观察

`ponyletter/py310GoofishAiBot` 的定位不是商品监控，而是闲鱼 AI 智能客服系统。它的核心价值在“买家消息处理”和“自动客服”，包括：

- 多专家 Agent：技术咨询、价格议价、默认对话分流。
- 意图识别：关键词、正则、大模型三级路由。
- 消息队列：异步处理、重试、死信队列、去重、优雅关闭。
- 安全过滤：微信、QQ、支付宝、银行卡、线下交易等违禁词拦截。
- 人工接管：通过关键词切换 AI / 人工模式。
- 本地模型：支持 Ollama 和 OpenAI 兼容接口。
- 对话记忆：聊天历史、上下文、议价次数统计。
- 语音提醒：用户输入状态播报。

这些能力适合放到本项目的“卖家自动回复 / 议价助手”扩展里，而不是直接放进商品监控流程。

## 下一步优先级

### P0

1. 验证 Docker 本地构建。
2. 验证钉钉通知设置页面。
3. 确认本地数据不会被更新覆盖。
4. 检查 Build Check 是否通过。

### P1

1. 结果页增加评分详情。
2. 通知卡片继续贴近视频效果。
3. 增加一键测试钉钉卡片。
4. 增加任务推荐阈值配置。

### P2

1. 透明评分：价格、卖家、图片、置信度。
2. 图片分析：实拍、清晰度、成色、网图风险。
3. 卖家画像：个人卖家、商家、回收、批发等判断。
4. 样本标注：推荐 / 不推荐，后续用于优化评分。

### P3

1. 自适应运行间隔。
2. 登录状态健康检查。
3. 代理质量统计。
4. 邮件通知。

### P4：自动客服扩展

1. 买家消息监听。
2. AI 自动回复。
3. 议价策略。
4. 违禁词过滤。
5. 人工接管开关。
6. Ollama 本地模型支持。

## 最终目标

轻量、好部署、通知好看、推荐可解释，并且适合个人长期运行。后续如果要做卖家端自动回复，再单独加入客服模块，不和商品监控主链路混在一起。
