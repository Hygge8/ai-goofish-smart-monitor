# 同类项目取舍分析

本项目以 `Usagi-org/ai-goofish-monitor` 为主底座，同时参考 `banbanzhige/ai-goofish-monitor-QB` 和 `ddCat-main/ai-goofish` 的设计方向。

## 取舍结论

| 项目 | 值得保留 | 不直接照搬 | 本项目做法 |
|---|---|---|---|
| Usagi | Web 管理、多任务、定时、账号与代理轮换、多渠道通知、Docker 部署 | 不再重复造基础框架 | 直接作为主底座 |
| QB | 三维评分、图片分析、卖家画像、钉钉图文卡片、样本标注 | 多用户、权限和 PostgreSQL 部署较重 | 优先吸收钉钉卡片、评分看板和样本标注思路 |
| ddCat | 轻量 Web、代理管理、频率控制、邮件通知、日志统计 | 当前框架已换成 Usagi，不替换主架构 | 吸收限速、健康检查、邮件通知和日志统计思路 |

## 已经合入

- 使用 Usagi 作为主框架。
- 保留 Web 管理、任务管理、账号管理、日志、结果、定时、多渠道通知。
- 增加钉钉 ActionCard 图文卡片。
- 钉钉正文不展示长链接，链接放到底部按钮。
- Docker 文档改为本仓库地址。
- 本地数据备份和恢复脚本已加入。

## 下一步优先级

### P0

1. 验证 Docker 本地构建。
2. 验证钉钉通知设置页面。
3. 增加 GitHub Actions 构建检查。
4. 确认本地数据不会被更新覆盖。

### P1

1. 结果页增加评分详情。
2. 通知卡片继续贴近视频效果。
3. 增加一键测试钉钉卡片。
4. 增加任务推荐阈值配置。

### P2

1. 透明评分：价格、卖家、图片、置信度。
2. 图片分析：实拍、清晰度、成色、网图风险。
3. 卖家画像：个人卖家、商家、回收、批发等判断。
4. 样本标注：推荐 / 不推荐，后续用于优化评分。

### P3

1. 自适应运行间隔。
2. 登录状态健康检查。
3. 代理质量统计。
4. 邮件通知。

## 最终目标

轻量、好部署、通知好看、推荐可解释，并且适合个人长期运行。
